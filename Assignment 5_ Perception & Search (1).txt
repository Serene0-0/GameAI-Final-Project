Assignment 5: Perception & Search
Due 3/11/26

In this assignment, we are going to move beyond our AI being magically aware of us, and add a simple perception system. This perception system will serve two purposes:

1. Perception State tracking:
The system will track how aware of the target each AI is.

2. New position predictions via an Occupancy Map:
The system (with your help) will generate predictions of the target's (i.e. the player's) position on timesteps when no AI is directly observing the target.

Perception systems are often simple conceptually, but the bookkeeping can get gnarly. For this assignment, most of the bookkeeping code has been provided. However, I highly recommend you look through the provided code before you start, to make sure you understand what is going on.

By the end of the assignment you should have some AIs that
? Becomes aware of the player when the player gets close with a clear line of sight
? Engage in some interesting search behavior when the player is no longer visible

Part 3: Fill Out GAPerceptionComponent
The GAPerceptionComponent is the component that will live on your AIs' controllers, and turns your AI into something that perceives things in the world.

Fill out UGAPerceptionComponent::UpdateTargetView()
This function determines whether a given target has a clear LOS to the perceiver, and also updates the perceiver's Awareness level of that target.


Part 4: Implement the Occupancy Map
The occupancy map for a target is stored on the UGATargetComponent itself. Note, it is worth looking at UGATargetComponent::TickComponent to get a sense of how the occupancy map works with the rest of the perception system.
There are three functions for you to fill out:

OccupancyMapSetPosition() - With this function, the OMap is being told that the target was directly perceived this tick. Therefore all probability should be cleared from the map, and the CELL representing the target's position should be set to 1.0 (i.e. all probably is stored in the one cell at which the target was observed).

OccuppancyMapUpdate() - The target was NOT observed this tick. Therefore we need to:
? Collect the set of cells that are visible to ANY AI (to be stored in the variable VisibilityMap
? Cull the probability from all visible cells
? Renormalize the distribution
? Update the "last known state" of the target

OccupancyMapDiffuse() - Whether the target has been observed or not, we need to diffuse probability across the grid.


Part 5: Retrofit your existing Code/Content
In previous iterations, we were giving our AIs direct access to the true position/velocity of their target (the player). However, our AIs should NOW be working only with the "last best guess" at the target's state. So part 4 is to go through past code/content and update your logic so that it is using the UGAPerceptionComponent::GetCurrentTargetState() function. Note, this can be called from both code and blueprint.

Note that if the target is unknown to the AI (UGAPerceptionComponent::HasTarget() returns false) then the call to GetCurrentTargetState will return false.

A Note on debugging
We've added two debugging modes to this perception system.
? BP_PerceptionComponent: set the member variable Debug to true in order render some lines to the last known position of the target. This is on by default.

? GATargetComponent: set the member variable DebugOccupancyMap to true in order render the occupancy map.
? Note: you can't debug your spatial functions and the Occupancy Map at the same time, so you might want to turn off debugging on the spatial component (turned on in assignment 3 in the BP_GAController).
